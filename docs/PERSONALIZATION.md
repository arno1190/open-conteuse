# Parent-owned personalization · assessment brief

20 November 2026. Proposed differentiation, not a live service. Assess provider/subscription compatibility later, as requested. No MCP server, paid TTS service, cloud account or background agent has been provisioned.

## Product proposition

Let a parent turn a learning goal, family interest or authorised subscription source into reviewed listening with little friction. Examples: a short lesson linked to this week’s interests; a fictional adventure with a parent-chosen theme; a reviewed podcast playlist. The parent controls sources, length, language and approval. The child listens to a stable local recording rather than interacting with an unrestricted model.

This differs from selling only a fixed catalogue. Our three original bilingual stories demonstrate a possible result, not a personalized-generation feature already operating. Lessons need factual/source checks appropriate to their subject; fiction must be clearly presented as fiction. No learning, therapeutic or developmental outcome is claimed.

## Integration candidates to assess

| Route | Potential use | Evidence required before claiming support |
|---|---|---|
| Parent’s AI-assistant subscription | Parent drafts a script using their chosen assistant; exports text/audio if their plan permits | Product/plan eligibility, export rights, supported tools/MCP transport, privacy/retention and actual audio-export capability |
| Provider API | Explicitly configured narration or drafting adapter | Separate API entitlement/billing, voice/language rights, cost limits, credentials, reproducibility and exact-byte review |
| MCP bridge | Bounded access between a compatible parent-selected client and the local content workflow | Client/plan support, local vs remote transport, authentication, per-tool authorization and tests |
| Files and recordings | Import a parent recording or authorised downloadable audio | Available in the local host foundation now; validate licence, bytes and device format |
| Podcast subscriptions | Parent-authorised episodes, including revision/dynamic-ad changes | Feed/access/download rights, credentials if needed, episode-byte review; do not scrape protected services or assume listening rights allow redistribution |

A ChatGPT/Claude/Gemini consumer subscription must not be represented as API credits, an exportable TTS licence or automatic MCP compatibility. Browser speech is a demonstration fallback, not a promised transferable provider recording. Account credentials stay with the parent or in a deliberately secured adapter; never on the child’s player or in Git.

## Proposed small MCP boundary

Start with discovery and drafts: list approved-library metadata, propose a bounded structured story/lesson draft, attach an explicitly provided audio file, inspect hashes/format/rights notes, and prepare an export preview. Tool arguments must follow schemas, use library identifiers instead of arbitrary filesystem paths, and bound sizes/durations. Imported text, feeds and model output are untrusted data.

Do not give an assistant an unrestricted shell, credential vault, child-profile export or an auto-approve-and-activate tool. Script approval and final audio approval remain distinct adult actions tied to exact bytes. A changed draft or recording invalidates approval. Content reaches a cartridge assignment only after approval. Background generation, new paid API calls and new source ingestion require the parent’s explicit configured scope and budget.

Transport choices remain open: local stdio for compatible local clients; authenticated loopback HTTP when supported; a remote HTTPS bridge only after a separate privacy/security assessment and explicit deployment scope. A local endpoint alone does not make it callable from a hosted assistant. The public showcase must never expose the parent studio.

## Parent UX target

One brief: topic/interest, age band, language, duration, purpose and allowed sources. Avoid requesting a child’s full name, school, location or sensitive profile. Show the script, sources/fiction label, proposed voice and cost/entitlement before narration. Let the parent listen, edit or reject; preserve previous approved revisions. Then offer one clear “prepare for player” step with transfer/status feedback. No silent replacement of a child’s saved story when a provider regenerates audio or a feed changes advertisements.

The passive cartridge ROM never needs rewriting: a parent can explicitly reassign its local selection. Preserve previous revisions and bookmarks, show what is changing, and keep the character/theme label meaningful to the child. A subscription update or AI regeneration must not silently replace a favourite.

Current local import/review/export and atomic host-library foundations are real. Assisted drafting/provider narration, unattended subscriptions, MCP, production transfer and integrated device playback are future milestones; do not collapse them into a claimed one-click finished feature.

## Assessment outputs before implementation

Select two real parent workflows and exact subscription plans; verify official capability/terms documentation and a manual end-to-end export. Compare manual file import, MCP and a separately billed API with actual cost, voice quality, parental effort and privacy tradeoffs. Define the smallest adapter and failure cases, then implement/test it against the existing approval boundary. No provider selection or binding commercial estimate is made here.
